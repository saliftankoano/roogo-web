# Changelog

What shipped, when. One line each, newest first. The *why* lives in
[`DECISIONS.md`](./DECISIONS.md); the *how it works* lives in
[`CONCEPTS.md`](./CONCEPTS.md).

## 2026-07-09

- **Sale chat: attachment timestamps are now readable** (mobile): image-only messages carry their HH:mm + ticks inside the picture on a dark scrim pill (WhatsApp pattern) and document chips carry theirs inside the chip; previously the meta floated under the attachment directly on the doodle wallpaper in 10px faint cream and was nearly invisible.
- **Sale chat sends are now optimistic** (mobile): a picked photo/document or typed text appears in the thread instantly as a pending bubble (local preview, dim + spinner overlay on images, clock instead of read ticks) while compression/upload/POST run; on success it swaps for the server message (realtime-duplicate safe), on failure it disappears with an alert stating why and a failed text send restores the draft. The thread also now opens at, and follows, the latest message (the FlatList previously had no scroll management, so a just-sent bubble could sit off-screen). Voice notes keep their recorder-bar pre-send UX.
- **Sale-chat push notifications now deep-link into the thread** (mobile): tapping a `sale_message`, `visit_requested`, `visit_confirmed`, or `notary_meeting` push opens `/sale-chat/{conversationId}` directly instead of just foregrounding the app. The backend already shipped `conversationId` in every one of those payloads; the mobile tap router (`routeNotificationData` in `app/_layout.tsx`) simply had no sale-chat case. One branch covers both sides since the thread screen resolves the caller's role server-side.
- **Fixed: voice notes could never upload** — the `sale-chat-attachments` bucket (created in 040/044) only allowed image mimes, so storage rejected the `audio/mp4` PUT with a 415 at upload time (signed-URL creation still returned 200, which hid the cause). Migration 049 extends the bucket allowlist to audio + the document types and lifts the file cap to 20 MB; also applied directly to the live bucket and verified with real audio/PDF PUTs against it. `postSaleMessage` additionally no longer sends `file_name` for attachments that lack one (voice/images), so attachment sends cannot break on a pre-048 database.
- **Document attachments in sale chat** (mobile + backend + admin): a paperclip in the mobile composer sends PDF and common office files (doc/docx, xls/xlsx, ppt/pptx, txt, csv) through the same signed-URL transport as images and voice notes; documents render as a tappable chip with the original filename (opens in the system viewer) on mobile and as a download link in /admin/sale-chat. Server-side mime allowlist at signed-URL creation, 20 MB client cap, migration 048 adds `sale_message_attachments.file_name`. New `expo-document-picker` dependency in the app. ([why](./DECISIONS.md#sale-chat-documents-ride-the-attachment-pipe-allowlisted--2026-07-09))
- **Sale chat is now property-anchored** (Facebook-Marketplace style): the property's cover photo identifies every conversation — inbox rows in the mobile Messages tab (48px rounded square, replacing the user avatar that made two threads look identical), the dark thread header (36px, replacing the Roogo logo), and /admin/sale-chat rows (40px thumbnail, previously no image). Both conversation endpoints now ship `property.cover_url`; this also fixed the thread endpoint returning no property join at all, so the mobile header finally shows "type · quartier" instead of "Conversation". Fallback is a neutral house-icon tile, never a user avatar. ([why](./DECISIONS.md#sale-chat-surfaces-anchor-on-the-property-not-people--2026-07-09))
- **Voice notes in sale chat** (mobile + backend + admin): mic in the composer when the field is empty, live timer with a 2 minute cap, mandatory playback preview with re-record and discard before anything uploads, AAC mono 32 kbps (a full minute costs less data than one listing photo). Playback bubbles in both mobile views and an audio player in /admin/sale-chat. Migration 047 adds message_type 'voice'. Also closed the chat screen's i18n gap (55 keys per catalog).
- **Sale chat rebuilt as an always-dark WhatsApp-style surface**: deep earth #17120f with a light-doodle wallpaper (contrast is structural, so the pattern can breathe), Roogo-avatar header, dark incoming bubbles with glowing terracotta outgoing, HH:mm timestamps with inline read ticks inside every bubble, and day separator pills. Overlay sheets stay light by design.
- **Sale chat team identity + wallpaper**: owners now see one unified Roogo identity (logo avatar + "Équipe Roogo") on all team messages, while staff and founders see WHO on the team wrote each message (first name, deterministic color) in both the mobile thread and /admin/sale-chat. Privacy is server-gated: owner API payloads never contain staff names. The thread also gets a WhatsApp-style seamless wallpaper of faint real-estate doodles on the brand sand tone. Voice notes are the agreed next block ([why](./DECISIONS.md#sale-chat-speaks-as-one-roogo--voice-notes-planned--2026-07-09)).

## 2026-07-08

- **Review hardening of the sale/terrain form work** (8 verified findings fixed): the terrain special case became a per-type capability map — `commercial` no longer demands a fictional bedroom/shower (rooms hidden, vehicles kept); sale payloads and the API now strip rental-perk amenities (wifi/meuble) that survived a rental→sale toggle; the web wizard's step-2 validation got the shared per-type rule back (an untouched counter no longer dead-ends at publish); pending edits and the staff PATCH route now enforce the sale guards server-side (no tenant rules or rental `period` writable onto sales, merged-state room validation on edits); and the mobile edit flow finally maps `listing_type` when loading a property (it previously treated every edit as a rental).
- **Listing form is now sale- and terrain-aware** (mobile + backend): sales no longer see the deposit card, "Total à l'entrée" move-in math, interdictions, or house rules, and amenities filter to physical assets (jardin/piscine/solaires/securite — wifi and meuble are rental perks); bare land (terrain) hides the bedroom/bathroom/vehicle counters (0 allowed end-to-end, backend maps to null) and requires superficie instead. Shared rule `requireListingFieldsByType` mirrored in `lib/validations.ts` (web) and `forms/listingSchema.ts` (mobile); the API also force-empties tenant rules on sales so old app builds can't write them. ([why](./DECISIONS.md#conditional-listing-form-for-sales--bare-land--2026-07-08))
- **Listing-form i18n consistency pass** (mobile): 11 missing English catalog entries added (all from the newer Sell + identity-verification features — "À louer/À vendre" toggle, "Prix net souhaité", the "Vendre avec Roogo" modal…), plus one hardcoded English error fallback now translated.
- **Fixed: every sale (vendre) submission failed** since Roogo Sell shipped — `properties.frequence` (migration 028) and `loyer_avance_mois` are NOT NULL in the live DB, but the API inserts NULL for both on sales, so the insert 23502'd and mobile showed the generic "Erreur lors de la soumission" (zero vendre rows ever existed). Root-caused by replaying the API's exact insert against the live DB. Fix: migration `046_sale_frequence_nullable.sql` (drop both NOT NULLs + a CHECK keeping them required for rentals). Mobile alert now appends the backend's actual error message (roogo repo).

## 2026-07-06

- **Support chat, now answerable from the phone** (app 1.16.0/61): staff & founders get a **Support** segment in the mobile Messages tab to list, open and reply to every user support conversation — previously website-only. Plus **read receipts** (✓ Envoyé → ✓✓ Lu) on both support and sale chat, on the bubbles and the admin consoles. ([why](./DECISIONS.md#support-console-goes-mobile--read-receipts--2026-07-06), [how](./CONCEPTS.md#how-is-the-mobile-app-authorized-to-hit-our-api-and-supabase))
- **Visites 3D hardening** after a multi-agent code review confirmed 7 defects: availability endpoint returned empty for everyone (anon key vs `security_invoker` view — verified against the live DB, switched to service role); payment completion unified into one atomic `finalizeVisit3dCompletion()` (kills double-SMS race, missing analytics, and the instant-COMPLETED no-SMS gap); PawaPay webhook no longer ACKs transient DB errors as "not found" (500 → retry) and can't regress a settled booking on redelivery; calendar can't select dates beyond the fetched availability window; the 15 000 FCFA price now derives from a single constant everywhere. Also fixed: Kuula collection embeds (embed.js doesn't render collections — plain iframe now). ([how](./CONCEPTS.md#how-do-visites-3d-payment-completions-stay-exactly-once))
- **Visites 3D** migrated from the Kazedra site to Roogo: public `/visites-3d` page (marketing + self-serve calendar booking + PawaPay Mobile Money payment + SMS confirmations), new single price of **15 000 FCFA / pièce** (old 10k/7.5k dual pricing retired), booking APIs under `/api/visites-3d/*`, shared PawaPay webhook now routes unknown depositIds to the `bookings` table. Kazedra deleted its 3D content and 308-redirects to us. ([why](./DECISIONS.md#visites-3d-move-under-the-roogo-brand--2026-07-06), how: [visites-3d.md](./visites-3d.md))
- Identity (KYC) verification is no longer required to post a listing — owners/agents can create rentals **and** sales without it; it's now surfaced as an optional, dismissible "get the badge" nudge in the add-property wizard. Staff still moderate every listing before it goes live. ([why](./DECISIONS.md#identity-kyc-becomes-optional--2026-07-06))
- **Roogo Sell** shipped as a broker/mandate model: seller↔Roogo and buyer↔Roogo per-property chat (no buyer↔seller contact), two-price spread instead of a 10% commission, in-app signed mandate + exclusivity, notary-meeting scheduling, and a `/admin/sale-chat` staff console. ([why](./DECISIONS.md#roogo-sell--broker-model-not-marketplace--2026-07-06), [how](./CONCEPTS.md#how-does-roogo-sell-the-broker-model-work))
